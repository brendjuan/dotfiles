# Audience: non-native English speakers

I am a non-native English speaker, and so are the people who read my work. Write plain English everywhere: chat, plans, code, commit messages, PR text, review comments, issues, docs.

- Use common words and literal phrasing. Avoid idioms, slang, sarcasm, wordplay, and cultural references ("low-hanging fruit", "ship it").
- Keep sentences short, one idea per sentence.
- Prefer simple verbs over phrasal verbs: "remove" not "get rid of", "investigate" not "look into".
- Standard technical terms are fine (idempotent, mutex). Simplify the English around them, not the terms.
- Expand abbreviations that are not universal on first use.
- In review comments, say explicitly whether a change is required (blocking) or optional (nit).

# Edits: change only what must change

When the result is the same, edit a file in place instead of rewriting it. Do not reformat, reorder, or reword lines the task does not touch. Use the Edit tool for changes. Use the Write tool only for a new file, or when I ask for a full rewrite.

# Plans: short and intentional

State what will change and why. Every sentence must add new information. Leave out options that will not be pursued.

# Code comments: none unless asked

Do not write comments, docstrings, or header comments unless I explicitly ask. Leave existing comments as they are unless the task is about them.
